# 当当说重设计：三个可操作概念与取舍

**结构上暂推荐 A「课堂收尾台」作为下一版主线。** 原因是它直接围绕“选一句，点一批孩子”组织主要工作，把不必要的步骤审批拿掉；这是一项专家评估，尚未经过老师计时或真实使用验证。B、C 保留为同一任务下可实际操作、可公平比较的替代结构，不是同一页面换颜色。

三方案共享业务事实，见 [01-约束与冲突.md](./01-约束与冲突.md)。这里讨论的是入口、注意力、回看与修正成本。

## 1. 先确定同一道题

使用同一场已下课课程、同一份空白记录和相同的库：10 位孩子，8 位到课，2 位请假；4 个能力方面、3 个特征方面；同样的教学内容、课堂素材、历史提醒与边界状态。

原型中的 4 个能力方面是语音基础、整体流畅、角色呈现、节奏语气。轮转的 3 个特征为专注力、情绪反应、音量。每个到课孩子要对这些方面作出表态，但不强迫老师逐个孩子打开档案。

共同的输入行为：

1. 挑选当前方面的一句现象。
2. 点所有符合它的到课孩子；同句可多人，后一选择可以覆盖前一选择。
3. 随时知道谁还没记；明确“未观察”与“尚未记录”的区别。
4. 最后确认要发给家长的内容；缺项给出到人、到事的定位。

共同的有效终点：只为 8 位到课孩子生成基于真实选择的报告，保留这次留下的具体下一课动作，能看见提交状态。原型模拟提交不等于已向真实家长发送微信通知。

依据：新规则:168、201、221、251。

## 2. 三种概念的真正差异

| 比较项 | A：课堂收尾台 | B：教学片段 | C：报告编校 |
|---|---|---|---|
| 老师第一眼看到的对象 | 这一班尚未完成的课后记录 | 刚才发生过的教学片段 | 即将交给家长的全班报告草稿 |
| 主问题 | 这一句符合谁，还有谁没记？ | 刚才练这个、演这个时，他们是什么样？ | 这份话有依据吗，还缺哪一项？ |
| 导航依据 | 当前观察方面与待记孩子 | 发音训练、作品演绎、课堂习惯 | 草稿中的缺失证据与待确认内容 |
| 记忆支撑 | 名单、教学内容作为紧邻上下文 | 教学内容和真实课堂材料帮助回忆 | 最终阅读结果帮助理解记录价值 |
| 批量操作发生处 | 同一记录工作区 | 当前片段内的记录工作区 | 某类缺失证据打开的全班补记录区 |
| 成果出现时机 | 记录后预览，可随时检查 | 片段记下后逐渐汇成报告 | 从一开始就看见报告结构；证据未填处保持空缺 |
| 主要风险 | 自由切换导致漏项、内容显得抽象 | 同一方面跨片段重复、按片段来回切换 | 阅读和校对压过记录、诱导逐人编故事 |

只改变这三种组织方式。判断阈值、句子库、到课名单、素材、发布条件不能跟着方案变化。

## 3. A：课堂收尾台

### 核心构想

老师进入的就是这一场课的收尾工作区。名单和本节内容是上下文，可以核对、可以查看；不会先经过一串“下一步”才能开始记录。主要区域始终服务一个动作：挑一句，将它分给符合的孩子。

观察方面可以直接切换，不需要先把当前方面填满才能看下一项。完成状态随分配即时更新，老师可按自己记得最清楚的部分先写。最后提交时，系统把遗漏定位到具体孩子和具体事情。

“仅提交校验”指不把完整性检查做成层层审批；不是让无效数据进入模型。未选句不能分配、请假不能记、未下课不能进入编辑、内容不匹配的观察不能算完成，这些约束仍即时成立。

### 预期优势

- 与主要工作量直接对应。规则明确具体表现占全部工作量的 80%，应让批量分配占据主要操作区域。新规则:194
- 名单、句子、已记状态在同一视野中，不因每次换孩子丢失上一句。
- 改错可原地完成；内容切换不会要求重新跑完已做过的步骤。
- 完整性由数据模型保证，减少老师为了“让流程继续”而点确认的动作。

### 主要代价与应对

- **初次使用是否知道从哪开始？** 默认聚焦一个有教学来源的待记方面，给一句明确引导；不同时铺开七组句子。
- **自由切换会不会漏项？** 始终可看“还有谁没记”，最后缺项提示回到相关位置；不把“所有格子都展示出来”当作唯一解法。
- **语音基础等词是否太抽象？** 用“刚才练双唇音时，孩子说得怎么样”说明来源；内部分类名不替代老师的判断语言。
- **报告价值是否不够早出现？** 完成记录后能预览实际给家长的内容；不用强迫老师每记一句就打开一份长报告。

需要被验证的假设：减少步骤切换带来的收益，大于自由选择带来的寻找成本。现在没有计时数据证明这一点。

## 4. B：教学片段

### 核心构想

老师先想起课堂，而不是先面对一组观察类别。入口用本节真实内容组织：

- **发音训练**：口腔准备与双唇音词卡，帮助回想孩子如何发音。
- **作品演绎**：本节故事作品，帮助回想完整讲述、角色声音、节奏语气。
- **课堂习惯**：本节只观察的三个性格方面，回想孩子贯穿课堂的状态。

进入片段后仍然先选句、再批量点人。每个片段是回忆入口，不是新的采集维度，也不要求每个片段重新遍历全部孩子档案。

### 去重是结构成立的前提

基本功与发音同时挂载语音基础时，只保留一份“学员 × 本课 × 语音基础”记录。不同入口引用同一当前记录，不能产生“在口腔操里选了一句，在拼版里又选一句”的冲突副本。跨片段再次进入时应回显已记内容。

老师改了内容，片段与所需记录一同更新；移除内容不等于静默清空仍被其他内容使用的记录。来源：新规则:185。

### 预期优势

- 内容与判断之间的因果关系直观，能减少老师对系统“为什么问这个”的疑惑。
- 对刚下课、课堂细节仍鲜明的老师，可能更容易回想具体表现。
- 拼版、作品名和已有素材各有明确用途，不为装饰放图片。

### 主要代价与应对

- **片段变多，可能增加切换。** 只按真实教学内容组织，不用每个小活动造一个入口。
- **同一表现可能发生在多个片段。** 记录去重，统一回显；若未来要区分场景，需要另做产品定义，不能本轮偷偷新增字段。
- **特征不是一段独立教学内容。** “课堂习惯”只是三个本节观察的回忆入口，不把另外三个未观察方面一起展开。
- **回忆顺序未必人人相同。** 允许直接切换，不要求照课堂时间顺序重走一遍。

需要被验证的假设：课堂回忆比按方面的整理更容易上手，并足以抵消片段切换成本。

## 5. C：报告编校

### 核心构想

老师一开始看见“这节课准备给家长留下什么”。草稿把已经确定的内容与缺失的证据区分开：已知的是孩子身份、教学名称、既有素材；尚未观察的地方只明确说还缺什么，不先伪造一份完整评语。

例如同一种“故事是否讲完整”的依据仍缺几位孩子，老师从这类缺口进入全班补记录区。她仍然挑一句、点多人，补完后对应孩子的草稿随证据更新。不会要求点开八个人、分别写八段话。

### 初稿的边界

- 来自人工维护的句子与确定的观察选择，不能引入 AI 写评语能力。
- 没有选定事实，就没有“今天主动举手”“演到某处停顿”等具体行为文案。
- 已有照片不自动证明孩子完成了某项能力；图片与行为判断分别由老师确认。
- 默认草稿不是默认同意，不用一组表扬话预填整个班。

依据：新规则:237、653。

### 预期优势

- 老师早早明白“我记录这一句，家长最后会读到什么”。
- 更适合晚上回看、补写和修改已经有部分事实的课次。
- 有利于发现素材错绑、老师的话与事实不相符、开头句不合适等内容问题。

### 主要代价与应对

- **空白班级变成八份待编文章，压力很大。** 缺口按问题聚合，不先铺八段完整空模板。
- **老师可能顺着漂亮文案反推评价。** 先呈现未完成证据，事实选定后才形成表达；不把默认优秀描述当起点。
- **容易滑向逐人编辑。** 进入缺口后仍处理全班；个人编辑只用于确实需要改的一句。
- **读文章会占用课后时间。** 区分“缺依据”和“已有事实待确认”；是否适合主入口必须通过计时验证。

需要被验证的假设：结果导向的清晰度能抵消读稿成本。专家评估认为它更适合补记与编校，但当前没有用户数据支持将它限制在该场景。

## 6. 为什么暂推荐 A

| 评价问题 | 专家判断 | 证据性质 |
|---|---|---|
| 哪个最贴近最高频动作？ | A 最直接：句子分给多人即为主要界面。B 在前面加入回忆入口，C 在前面加入成文结果。 | 来自任务分解，尚非实测速度。 |
| 哪个最不容易误把产物当证据？ | A、B 直接记录现象；C 需要特别防止从漂亮草稿反推孩子表现。 | 基于失误风险评估，尚无错误率数据。 |
| 哪个便于按个人记忆先后补写？ | A 自由切换最少依赖外部结构；B 需找到片段；C 需找到缺口。 | 结构推断，仍需观察首次使用寻找行为。 |
| 哪个对第一次使用可能更友好？ | B 的教学片段可能比抽象方面更自然；A 需要清晰上下文；C 的结果可见也可能帮助理解。 | 目前不能判定胜者。 |
| 哪个可能适合晚上修订？ | C 的缺口和成文对照具有优势；A 的原地改错也可能更省时。 | 场景假设，待验证。 |
| 哪个更容易保持克制？ | A 可让一个主动作主导屏幕，但也可能做成密集操作台；B、C 同样可以克制。 | 克制取决于实现，不能由方案名字保证。 |

因此推荐是：**以 A 为主结构，保留 B 的内容来源提示和 C 的真实预览价值，但不把三种入口全部塞进同一屏。** 否则又会用“覆盖所有优点”制造导航负担。

推荐可能被推翻：如果真实老师在 B 中明显更少犹豫和误选，且完成时间不劣于 A，应优先 B；如果 C 对新手的理解优势明显，并未引发逐人编辑，应重新评估其作为主入口的价值。

## 7. 家长体验不随概念任意变动

三方案完成同一组观察后，应该得到相同事实的家长内容。对比的重点是老师怎样完成记录，不是让 C 拿到更漂亮的报告、让 A 使用更差的文案。

家长先得到一个具体瞬间，再看有依据的“以前 / 现在”、老师的话与素材。长期特点和成长历程可进一步查看。六个答案必须可达，展示不必对应六张卡或六个页面。新规则:387、723。

阶段结论不能凭前端随意拼接。原型只能使用明确标识为示例的既定结论与历史资料；上线时需接真实规则服务。分享、通知、账号授权同样区分“界面可演示”与“生产服务已接通”。

## 8. 同场比较怎么做

以下是待执行的比较方法，不是已经取得的结果。

### 自动化与人工功能核对

每种结构必须跑同一组任务：

- 空白记录开始，确认只包含八位到课孩子；分别选句并批量分配。
- 使用“这节没观察到”，验证它能完成表态而不生成虚假数值结论。
- 给同一孩子改选另一句，检查覆盖和当前回显。
- 从基本功和发音进入同一方面，检查不重复计数。
- 漏一项直接提交，检查定位和未完成孩子计数。
- 不上传素材提交，检查不会被图片要求阻断。
- 标重点不写动作提交，检查保留其他输入并指向具体缺口。
- 提交失败后重试，检查数据不丢失、不会重复生成。
- 撤回再修改，检查家长旧版持续存在，重提后再更新。

功能完成与业务正确性是第一道门槛。截图没有证明这些行为，脚本通过也没有证明老师觉得自然。

### 老师使用观察

使用 390×844 左右的手机视口，要求老师独立完成相同班级，不由演示者口头指导。每次从同一份空白场景开始；方案顺序应轮换，避免第三个方案因熟悉题目天然更快。

记录：完成总时间、首次找到操作的时间、需要帮助的次数、误点或改选次数、遗漏如何被发现、是否能解释“这节没观察到”的意义、最后能否说出家长会收到什么。把单纯点击时间与阅读、思考、返工时间分开看。

三分钟是需求目标，不是现有结论。八人场景通过后仍需更大班级和不同教学内容验证，不能把一个演示样本推广到所有班级。

### 家长阅读观察

家长在相同事实的报告中阅读，观察能否在两分钟内说出孩子今天的具体行为、一个有依据的变化，以及老师真正关注的细节。愿意分享的理由应追问到内容，不能只问“好不好看”。

## 9. 自动演练可以量化什么

后续收到实际自动化路径时，按下面口径记录。**自动脚本路径可以证明某条路径可走、用了多少显式动作；不能证明人类找得到、理解得了，或三分钟内做得完。**

### 事件与指标定义

| 指标 | 统计边界 | 允许作出的结论 | 不能推出的结论 |
|---|---|---|---|
| 显式点击次数 | 从原型任务入口后的首个业务点击，到最终提交反馈；计真实 UI 点击。重置场景、切概念、截图、测试面板操作不计入业务路径。 | 指定路径实际触发多少次点击。 | 点击少即更快、认知成本低、老师更喜欢。 |
| 文本输入 | 单列输入字段数、输入字符数、粘贴/键入方式。自动 `fill` 一个字段不等于人类输入一次动作。 | 路径是否要求额外文字、要求多少内容。 | 填写耗时和老师构思耗时。 |
| 方面切换次数 | 记录当前能力/特征内部键发生变化的次数，回到已记项也计；直接初始化不计。 | 该路径在几个记录对象间切换。 | 人的注意力切换、迷失次数或心理负担。 |
| 页面切换与面板打开 | 主页面导航、抽屉/浮层打开、内容片段切换分别计数；不混成一个“步骤数”。 | 哪种界面跳转实际发生。 | 无页面跳转就更容易理解。 |
| 记录完成数 | 八人 × 四能力为 32，八人 × 三特征为 24；未观察计表态完成，但另列未观察数。 | 所选场景被完整覆盖，缺项计数正确。 | 观察真实、评判准确，或老师确实认真看过每人。 |
| 批量分配效果 | 一次选句后分配的不同孩子数量；明确区分逐个点八人和“全选到课”一个操作。 | 一句能覆盖多人，模型没有错误复制身份。 | 老师应当给所有孩子相同句子，或一次全选必然合理。 |
| 状态等价性 | 相同输入完成后，比对观察 ID/原文、孩子归属、未观察标识、媒体归属、重点动作和报告数量；排除运行时间、随机 ID 等非业务差异。 | 三方案执行相同业务时产生等价数据。 | 三方案体验相同。 |
| 边界断言 | 每项列通过、失败、未运行；注明具体输入与最终状态，不能把测试入口存在当通过。 | 被执行的边界行为符合约定。 | 未覆盖的所有异常都已正确。 |
| 自动演练耗时 | 浏览器单调时钟记录首个业务事件至最终断言；注明运行环境、固定等待、网络模拟、浏览器版本和视口。 | 这次脚本运行耗时多少，可用于性能排障与复现。 | 老师实际完成时间、阅读时间或“达到三分钟目标”。 |
| 布局检查 | 在指定视口检测横向溢出、控件遮挡、图片加载、交互热区和正文尺寸；与人工截图检查分开。 | 指定页面状态在指定视口的技术表现。 | 高级审美、情绪共鸣或真实可读性已经被验证。 |

### 公平比较的控制条件

- 每个概念都从同一版本的空白场景开始；不可让 C 预填观察而让 A 从零输入。
- 用相同的记录结果，包含分组不同的孩子，避免“一键把所有人选成同样”得到不具代表性的最短路径。
- 同样执行一次改选、一次未观察、一次缺项定位与一次合法提交。正常路径和异常路径分开报告，不混为一个总耗时。
- 不用直接写入 localStorage、调用内部状态 setter 或注入完成态替代用户操作。若测试数据初始化使用这些方式，明确隔离在计数起点之前。
- 若某方案为了抵达同一结果需要更多滚动或面板展开，照实记录，不通过调用隐藏 DOM 或强制点击来规避布局成本。
- 不只报告自动寻优后的最少点击。应保存实际执行顺序，说明是否存在快捷路径、测试者是否事先知道按钮位置。

### 结果写法

可写：“在固定八人场景中，脚本按预定路径点击了 X 次，产生 32 条能力表态和 24 条特征表态；缺项阻断、请假排除等 Y 项断言实际执行并通过。”

不可写：“X 次点击，所以三分钟完成”“脚本 Z 秒，老师也只需 Z 秒”“全部通过，因此用户一定觉得顺手”。

真实数据到达前，X/Y/Z 均不填估计值。本文件的 A 推荐仍是专家结构评估，不因自动演练更短就自动升级为用户验证结论。
